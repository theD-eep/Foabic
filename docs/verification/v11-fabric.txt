Fake-player bridge harness
--------------------------
A temporary Fabric-only self-test mod (not shipped) placed the Foabic test block
with a FakePlayer and invoked the real Fabric callbacks:

  SELFTEST_BLOCK_ENTITY=example.MinimalMod$TestBlockEntity
  SELFTEST_INTERACT=Success[swingSource=PREDICTED, itemContext=...]
  SELFTEST_BREAK_ALLOWED=true

The Foabic example observed the corresponding signals:

  FOABIC_INTERACT player=[Minecraft] block=foabic_test:test_block pos=0,100,0 hand=MAIN_HAND
  FOABIC_BREAK player=[Minecraft] block=foabic_test:test_block pos=0,100,0
  FOABIC_TICK platform=fabric tick=20 players=0

This proves block-entity creation and both new player signals through the real
Fabric event path, not just registration.

Duplicate-ID runtime test
--------------------------
A byte-identical copy of the example jar was added under a second file name.
The server continued to start and loaded exactly one copy:

  严重: 发现重复的 Mod ID: foabic_test，已跳过加载 (...\zzz-duplicate.jar); 已加载自 ...\foabic-example-minimal-1.1.0.jar
  信息: Foabic loaded 1 mod(s) in 72 ms on fabric
  信息: FOABIC_STATUS platform=fabric block_registered=true item_registered=true block_entity_registered=true sound_registered=true

No exception was thrown and the duplicate was skipped.

Dependency-error runtime test
-----------------------------
A temporary Foabic mod declared:
  depends=fabric-api@>=99.0.0

The installed Fabric API was 0.166.2+26.3. The loader stopped before loading
the mod entrypoint with this single clear line:

No NoClassDefFoundError was raised.
