Fake-player bridge harness
--------------------------
A temporary NeoForge-only self-test mod (not shipped) placed the block and
posted the real NeoForge events:

  SELFTEST_BLOCK_ENTITY=example.MinimalMod$TestBlockEntity
  SELFTEST_INTERACT canceled=true result=Success[swingSource=PREDICTED, itemContext=...]
  SELFTEST_BREAK canceled=false

The Foabic example observed the corresponding signals:

  FOABIC_INTERACT player=[Minecraft] block=foabic_test:test_block pos=0,100,0 hand=MAIN_HAND
  FOABIC_BREAK player=[Minecraft] block=foabic_test:test_block pos=0,100,0
  FOABIC_TICK platform=neoforge tick=20 players=0

The canceled=true interact event is the expected NeoForge mapping for
PlayerInteractBlockSignal.Result.SUCCESS. The break signal did not cancel, so
the event remained uncanceled.

Limits
------
This is a dedicated-server test. No client was launched, so the rendered
models/textures were not visually inspected. The generated pack files and
namespace discovery were verified; the client resource-reload path was not
executed. See docs/VERIFICATION.md.

The NeoForge runtime emits its usual Netty epoll/kqueue Windows environment
warnings. They are runtime noise, not Foabic load failures; the server reached
Done and all Foabic assertions passed.
